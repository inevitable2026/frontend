# 더미 문서 세트

시나리오의 감지 조건 여덟 건을 **실제 파일로** 먹이기 위한 문서 묶음이다. 데이터베이스에
행을 꽂는 것이 아니라 HTML 로 서식을 짜고 PDF 로 뽑아 기존 인제스트 파이프라인
(`POST /api/context/ingest` → SSE 8단계)에 그대로 올릴 수 있게 만들었다.

문서는 **18건 · 57쪽**이고 전부 허구다. 원천은 `docs/scenario-gimpo-logistics.md` 이며
회사명과 인물명은 그 문서의 것을 그대로 쓴다 — 새로 지어내지 않았다.

---

## 다시 만드는 법

```bash
node scripts/make-docs/build.mjs            # HTML + PDF 전부
node scripts/make-docs/build.mjs --list     # 목록만
node scripts/make-docs/build.mjs --only tbm # id 에 tbm 이 들어간 문서만
node scripts/make-docs/build.mjs --html-only  # PDF 변환 건너뛰기
node scripts/make-docs/build.mjs --clean    # 산출 디렉터리를 비우고 다시
node scripts/make-docs/build.mjs --out /어디/든  # 산출 위치 바꾸기
```

산출은 `scripts/make-docs/out/html/*.html` 과 `scripts/make-docs/out/pdf/*.pdf` 다.

**의존성을 하나도 추가하지 않았다.** Node 표준 라이브러리와 시스템에 이미 깔린
Chrome 한 줄이 전부다.

```
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf=/절대경로/out.pdf "file:///절대경로/in.html"
```

`CHROME_PATH` 환경변수로 다른 실행 파일을 지정할 수 있다. Chrome 을 못 찾으면 빌드가
멈추므로 `--html-only` 로 HTML 까지만 만들면 된다.

### 이 경로에서 밟은 함정

- **입력은 반드시 `file://` + 절대경로다.** 상대경로를 주면 조용히 빈 페이지가 나온다.
  `--print-to-pdf` 값도 절대경로여야 한다. `lib/pdf.mjs` 가 둘 다 검사한다.
- Chrome 이 stderr 로 `Trying to load the allocator multiple times.` 를 뱉는데 무해하다.
  **성공 판정을 stderr 로 하면 안 된다.** exit code 와 산출 파일의 `%PDF` 매직으로 본다
  (`pdf인가()`).
- **`position: fixed` 로 쪽마다 반복되는 고지를 붙이려 하면 안 된다.** Chrome 의
  `--print-to-pdf` 는 본문 상자 밖으로 밀린 fixed 요소를 잘라 버린다 — `bottom: -13mm` 로
  두면 아예 그려지지 않는다. 대신 문서 전체를 바깥 표 하나로 감싸고 고지를
  `<thead>`(`display: table-header-group`)에 넣었다. 실측으로 확인했다: 40mm 짜리 머리를
  thead 에 넣으면 120행 표가 3쪽에서 4쪽으로 늘고, tbody 에 넣으면 늘지 않는다.
  즉 thead 쪽이 매 쪽 다시 그려진다.
- 한글은 `AppleSDGothicNeo-Regular/Bold/SemiBold` 가 PDF 에 임베드된다. 깨지지 않는다.

### `.gitignore` 한 줄이 필요하다

레포 루트의 `/out/` 만 무시되고 `scripts/make-docs/out/` 은 무시되지 않는다.
산출물이 `git status` 에 뜨는 것이 싫으면 `.gitignore` 에
`scripts/make-docs/out/` 을 넣어야 한다. **이 작업에서는 `.gitignore` 를 건드리지
않았다** — 읽기 전용으로 취급하라는 지시가 있었다. 아니면 `--out` 으로 루트 `out/` 을
가리켜도 된다.

## 모든 문서가 지키는 것

| 규칙 | 어떻게 |
| --- | --- |
| 가상 고지 | 쪽마다 반복되는 붉은 머리띠 + 문서 끝 꼬리말. `lib/render.mjs` 의 `고지문` |
| 법령 인용 | **조문 번호와 제목까지만.** 조문 본문은 어느 문서에도 없다 |
| 실명 금지 | 회사·인물·기관 이름은 전부 시나리오 문서의 허구 이름. 금액은 도급액을 포함해 어디에도 적지 않았다 |
| 표 | 모든 문서에 최소 두 개 이상의 실제 표. 「표·서명인식」 단계가 볼 것이 있다 |
| 서명·도장 | 서명 줄과 날인 원, 결재란(담당·공무팀장·안전관리자·현장소장), 접수인, 직인 자리를 실제로 그렸다 |

법적 근거란에 적히는 형태는 이렇다 — 이 이상은 문서에 없다.

```
「산업안전보건기준에 관한 규칙」 제332조(거푸집 및 동바리의 구조)
```

### S-02 이행확인 미표시 (일정 규칙)

02 8월 회의록의 이행확인란 공란 **9행**(연번 2,5,6,12,13,14,17,19,20)이다.


`kind` 는 위 문서표의 「종류」 열을 그대로 쓴다. 현장 자동 판정은 문서 안의
현장명 「김포 고촌 물류센터 신축공사」로 걸린다 — 로마자 현장명은 trigram 유사도가
0 이라 죽는다는 `HANDOFF.md` 의 함정을 피하려고 모든 문서 머리에 한글 현장명을 넣었다.

인제스트를 거친 문서의 `출처등급`은 **`합성`** 이다. 화면에 그 배지를 그대로 드러내야
한다 — 발표자가 입으로 하는 고지는 나중에 혼자 열어 보는 사람에게 남지 않는다.
그래서 문서 자체에도 쪽마다 붉은 고지를 박았다.

## 파일이 어디에 있나

```
scripts/make-docs/
  build.mjs                     실행기. --list · --only · --html-only · --out · --clean
  lib/render.mjs                서식 헬퍼. 고지 · 표 · 서명란 · 결재란 · 접수인
  lib/pdf.mjs                   Chrome 호출과 %PDF 검증
  data/site.mjs                 현장 · 회사 · 인물 상수 (전부 허구)
  data/risk-rows-july.mjs       7월 정기평가 14행 + 시스템동바리 전제
  data/risk-rows-august.mjs     8월 회의록 21행 + 추천값 + 지적 대상 계산
  data/attendance.mjs           출역 인원 생성기 (결정론적) + 신규 11명
  documents/*.mjs               문서 한 건씩. index.mjs 가 우선순위 순으로 모은다
  out/html/*.html               산출 (18건)
  out/pdf/*.pdf                 산출 (18건 · 57쪽)
```

인물 이름은 `data/attendance.mjs` 의 결정론적 생성기(LCG, seed 20260819)로 만든다.
