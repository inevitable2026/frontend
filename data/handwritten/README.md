# 손으로 쓴 원본 문서

`board.snapshot_facts` 에 들어 있는 사실 86건은 OCR 로 뽑아낸 값이라는 설정이지만, 정작 그
값이 나온 원본 문서가 데이터베이스에 없었다. 김포 고촌 물류센터(`BOARD_SITE_ID` =
`0198a1d4-6c3f-4b2a-9e51-3f8c6b0d21ae`)의 `public.documents` 는 0건이었고, 문서함 화면과
브리핑의 "새 문서 N건" 이 그래서 늘 비어 있었다.

이 디렉터리는 그 빈자리를 채우려고 만든 **수기 작성 원본의 스캔본**이다. 현장에서 사람이
볼펜으로 채운 서식을 복사기로 밀어 넣은 것처럼 보이게 만들었다 — 종이 질감, 기울어진 스캔,
정정 사선, 붉은 여백 메모, 도장까지 들어 있다.

## 무엇을 재현했는가

원본은 `scripts/make-docs/` 가 HTML 로 짜서 PDF 로 뽑아 둔 활자 문서 21건이다. 그 문서의
**표와 값을 그대로 옮겨 적었다.** 감지 조건 여덟 건이 읽어야 하는 숫자와 공란이 특히 중요해서
프롬프트에 값을 하나씩 박아 넣었다.

- 8월 회의록의 법적 근거란 공란 12행 · 개선 후 위험도 미기재 7행 (T-04 의 지적 19행)
- 기상 기록부의 주말 누적 강우 41.0mm 대 임계치 30.0mm (T-01)
- TBM 회의록 세 회차에 걸쳐 이월되는 `F-0817-1` 과 끝내 비어 있는 조도 확인란 (T-02)
- 7월 평가표 1항의 「대체 공법 검토: 없음」 전제와 그 위에 선 4층 슬래브 8행 (T-03)
- 8월 회의록 연번 8 의 이행확인 ✔ 와 아차사고 보고서의 「실제 미실행」 대조 (T-05)
- 결재 대장의 미상신 8건과 제출 기한 2026-08-24 (T-06)
- 부록 A 의 연번 7 추천값 5×4=20 대 등재값 4×3=12, 이격 8 (T-07)
- TBM 08-19 참석자 명단에서 빠진 신규 입장자 8명 (T-08)

## 어떻게 만들었는가

`gpt-image-2` 로 한 쪽씩 생성했다. 한글 손글씨 폰트가 이 기기에 하나도 없어서 폰트를 받는
대신 이미지 생성으로 갔다. 실측해 보니 문서번호(`GGC-01-TBM-20260818-골조A`), 관리번호
(`F-0817-1`), 위험도 계산식(`2×3=6`), 빈 칸의 위치까지 상당히 정확하게 재현된다.

세로 문서는 `1024x1440`, 표가 넓은 문서는 가로 `1440x1024` 로 뽑고 품질은 `high` 를 썼다.
PNG 원본 61MB 를 JPEG 품질 82 로 줄여 11MB 로 넣었다. 원본 PNG 는 세션 임시 디렉터리에만
있고 레포에는 없다.

## 논리 docId 와의 대응

보드의 카드와 사실은 문서를 `ra_2026_07_regular` 같은 **논리 이름**으로 가리키는데, 화면
(`components/task-board/view-model.ts:1134`)은 그 문자열로 `documents.id`(uuid)를 찾는다.
지금은 둘이 영원히 맞지 않아 무효화 칩을 눌러도 원본으로 이어지지 않는다. 적재할 때 아래
대응을 어딘가에 명시적으로 남겨야 한다.

| 논리 docId | 이 디렉터리의 파일 | 쓰이는 곳 |
| --- | --- | --- |
| `ra_2026_07_regular` | `01-ra-2026-07-regular-*` | `board.invalidations` 7건 |
| `ra_2026_08_regular` | `02-ra-2026-08-minutes-*` | `board.invalidations` 19건 |
| `tbm_20260818_pour` | `07-tbm-20260818-*` | `board.invalidations` 4건 |
| `doc_2_k3f9x1qm` | `03-seojin-material-letter-*` | `snapshot_facts` 5건 |
| `doc_5_p8w2zzt1` | `04-seojin-shoring-spec-*` | `snapshot_facts` 2건 |
| `doc_9_r4m6yq` | `05-supervisor-correction-*` | `snapshot_facts` 3건 |
| `doc_11_v2n8ha` | `17-labor-notice-*` | `snapshot_facts` 3건 |

원본 HTML 하단에도 논리 식별자가 박혀 있지만 시드 사실의 값과 일부 어긋난다 — 05 문서는
HTML 에 `doc_7_v2n8qlxa` 로 적혀 있고 시드는 `doc_9_r4m6yq` 를 쓴다. **시드 쪽 값이 기준이다.**
위 표가 그 기준으로 적혀 있다.

## 아직 하지 않은 것

여기서 작업이 멈췄다. 남은 것은 넷이다.

1. **이미지 6장이 빠져 있다.** 09 출역 이력 기준 집계(2쪽)와 10~13 일일 출역 명부 4일치가
   아직 없다. T-08 의 재료라서 신규 입장자 판정을 원본으로 되짚으려면 필요하다.
2. **PDF 로 묶지 않았다.** 문서 한 건이 여러 쪽이므로 쪽 이미지를 문서 단위 PDF 한 벌로
   합쳐야 한다. `scripts/make-docs/lib/pdf.mjs` 의 Chrome headless 경로를 그대로 쓰면 된다 —
   이미지를 `<img>` 로 배치한 HTML 을 만들어 `--print-to-pdf` 로 넘기는 방식이다.
3. **데이터베이스에 넣지 않았다.** `public.documents` 에 행을, `public.document_files.bytes`
   에 PDF 본문을 넣어야 한다. `GET /api/context/documents/[documentId]/file` 이 이미 그
   바이트를 그대로 내려주므로 라우트는 새로 만들 것이 없다. OCR 파이프라인은 태우지 않기로
   했으므로 `document_chunks` 는 비워 둔다 — 문서 검색은 이 문서들에 대해 작동하지 않는다.
4. **논리 docId 를 잇지 않았다.** 위 대응표를 `documents` 의 컬럼이나 별도 매핑 표로 남기고,
   `view-model.ts` 의 `문서사전` 조회가 그 이름으로도 찾을 수 있게 해야 한다.
